## 1. 设计目标

- 按页面切片组织前端工程，便于 AI 分批生成与逐步修改。
- 所有请求走统一 Axios 封装，不直接在组件中调用。
- 所有状态按模块划分 Pinia Store，避免组件间状态混乱。
- 路由与权限分离，登录拦截与角色路由清晰。
- 与《05-API设计文档》保持严格一致，字段名不自行编造。

### 1.1 前后端分离与整体仓库结构

项目采用**单仓库多工程**模式，前后端完全分离。

```text
coffee-platform/
├── docs/                        # 项目文档
├── backend/                     # Spring Boot 后端工程
├── frontend/                    # Vue3 前端工程（本文档重点）
├── deploy/                      # Docker Compose、Nginx、初始化 SQL
└── scripts/                     # 本地启动脚本
```

- 前端工程根目录：`frontend/`
- 后端工程根目录：`backend/`
- 开发环境：前端 `http://localhost:5173`，后端 `http://localhost:8080`
- 前端通过 Vite 代理 `/api` 到后端，避免跨域
- 生产环境：Nginx 托管前端静态文件，并将 `/api` 反向代理到后端
- 前后端字段严格按《05-API设计文档》对齐，不自行编造

## 6. Axios 封装设计

### 6.1 request.ts 核心逻辑

ts

```
// utils/request.ts
import axios from 'axios'
import { useUserStore } from '@/stores/user'
import { ElMessage } from 'element-plus'
import router from '@/router'

const service = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000
})

// 请求拦截：注入 Token
service.interceptors.request.use(config => {
  const userStore = useUserStore()
  if (userStore.token) {
    config.headers.Authorization = `Bearer ${userStore.token}`
  }
  return config
})

// 响应拦截：统一处理 code、401、错误提示
service.interceptors.response.use(
  response => {
    const res = response.data
    if (res.code === 0) {
      return res.data
    }
    if (res.code === 401) {
      const userStore = useUserStore()
      userStore.logout()
      router.push('/login')
    }
    ElMessage.error(res.message || '请求失败')
    return Promise.reject(new Error(res.message || 'Error'))
  },
  error => {
    ElMessage.error(error.message || '网络异常')
    return Promise.reject(error)
  }
)

export default service
```

### 7.2 路由守卫

ts

```
// router/guard.ts
router.beforeEach((to, from, next) => {
  const userStore = useUserStore()
  if (to.meta.requiresAuth && !userStore.token) {
    next({ path: '/login', query: { redirect: to.fullPath } })
    return
  }
  if (to.meta.requiresAdmin && !userStore.isAdmin) {
    next({ path: '/' })
    return
  }
  next()
})
```

## 10. 前端修改三遍法

### 第一遍：能跑

- 页面能打开、路由能跳、请求能发出去。
- 确认 `npm run dev` 不报错。
- 确认 Axios baseURL、Token 注入、401 跳转正常。

### 第二遍：能用

- 替换 mock 数据为真实 API。
- 补 TypeScript 类型。
- 处理 loading、空状态、错误提示。
- 表单校验、提交、重置。
- 分页、搜索、筛选。
- 状态放入 Pinia。

### 第三遍：好维护

- 抽公共组件。
- 请求逻辑抽到 `src/api/`。
- 类型抽到 `src/types/`。
- 组合式逻辑抽到 `src/composables/`。
- 统一错误处理、日期格式、金额格式。
- 删除 AI 生成的重复代码和硬编码。
