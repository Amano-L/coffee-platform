## 1. 引言

### 1.1 目的
本文档定义咖啡电商与订阅平台的功能需求与非功能需求，作为系统设计、开发、测试与验收的依据。本文档覆盖 P0 与 P1 功能，P2 功能不在本文档范围内。

### 1.2 范围
系统面向消费者与运营管理员，提供咖啡商品浏览、购物车、下单、支付、库存管理、订阅配送与后台管理等能力。核心目标是跑通“用户 -> 商品 -> 订单 -> 支付 -> 库存 -> 订阅”完整闭环。

### 1.3 术语
| 术语     | 说明                                          |
| -------- | --------------------------------------------- |
| SKU      | 库存量单位，如 250g 整豆、500g 研磨           |
| 订阅     | 用户按周期（周/月）自动获得咖啡配送的服务     |
| 预占库存 | 下单时冻结库存，支付成功后真实扣减            |
| 幂等     | 同一请求多次执行结果一致，防止重复扣款/扣库存 |
| 状态机   | 订单/订阅在有限状态间按规则流转               |
| 逻辑删除 | 通过 `deleted` 字段标记删除，数据不物理删除   |

## 2. 总体描述

### 2.1 产品定位
学习型作品集项目，以咖啡电商 + 订阅制为业务外壳，覆盖 Spring 后端核心能力：鉴权、CRUD、事务、状态机、并发库存、缓存、消息队列、定时任务、支付回调、后台管理。

## 4. 核心业务规则

### 4.1 订单状态机
```text
待支付(30min超时) -> 已支付 -> 待发货 -> 已发货 -> 已完成
待支付 -> 已取消
已支付 -> 退款中 -> 已退款
```

### 4.2 库存规则

1. 下单时预占库存（冻结），支付成功后真实扣减。
2. 取消订单或超时释放预占库存。
3. 库存扣减使用乐观锁 + 条件更新 `stock >= #{num}`，防止超卖。
4. 每次库存变更记录 `inventory_log`。

### 4.3 订阅规则

1. 每日凌晨定时任务扫描到期订阅，自动生成待支付订单。
2. 用户可暂停、跳过、取消订阅。
3. 订阅订单与普通订单共用订单状态机。
4. 暂停期间不生成订单，跳过则下次周期顺延。

### 4.4 支付规则

1. 支付回调必须幂等，重复回调不重复修改订单状态和扣减库存。
2. 支付单号唯一，回调需验签。
3. 支付成功后触发库存真实扣减、订单状态流转、通知发送。

## 6. 数据需求

- 所有表包含 `id`、`create_time`、`update_time`、`deleted`。
- 金额使用 `DECIMAL(10,2)`。
- 字符集 `utf8mb4`，引擎 InnoDB。
- 核心唯一索引：`user.username`、`order.order_no`、`payment.pay_no`。

## 7. 验收标准

- P0 功能全部可用，且能通过 Postman/Swagger 完整演示。
- 前端页面能正常调用 P0 接口，无阻塞性 Bug。
- 核心链路通过并发测试（100 并发下单不超卖）。
- 支付回调具备幂等性，重复回调不产生脏数据。
- 订阅定时任务能正确生成订单并流转状态。
- 所有接口具备统一响应格式与全局异常处理。
