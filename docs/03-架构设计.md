## 1. 架构目标

- 跑通“用户 -> 商品 -> 订单 -> 支付 -> 库存 -> 订阅”核心闭环。
- 保持模块边界清晰，便于后续拆分微服务。
- 控制复杂度，避免过早引入分布式事务、分库分表、多租户。
- 覆盖 Spring 后端核心能力：鉴权、事务、状态机、并发库存、缓存、消息、定时任务、幂等。
- 支撑 AI 辅助前端开发，保证接口契约稳定。

## 2. 总体架构

采用 **模块化单体（Modular Monolith）** 架构。

                               │ HTTP / JSON

┌─────────────────────────────────────────────────────────────┐
│                   Spring Boot 3.x 单体应用                   │

## 3. 分层架构

text

```
┌─────────────────────────────────────────┐
│              Controller 层               │  参数校验、DTO 转换、返回 VO
├─────────────────────────────────────────┤
│               Service 层                 │  业务逻辑、事务边界、状态机
├─────────────────────────────────────────┤
│                Mapper 层                 │  MyBatis-Plus、复杂 SQL XML
├─────────────────────────────────────────┤
│              Infrastructure              │  Redis、RabbitMQ、定时任务、外部接口
└─────────────────────────────────────────┘
```



### 3.1 分层职责

| 层             | 职责                                           | 禁止                        |
| :------------- | :--------------------------------------------- | :-------------------------- |
| Controller     | 接收请求、参数校验、调用 Service、返回统一响应 | 写业务逻辑、直接调用 Mapper |
| Service        | 业务逻辑、事务、状态机、领域规则               | 直接操作 HttpServletRequest |
| Mapper         | 数据库访问、SQL 映射                           | 写业务逻辑                  |
| Infrastructure | 缓存、消息、定时任务、外部调用                 | 侵入业务逻辑                |

## 4. 模块划分

text

```
com.coffee
├── common        (通用：统一响应、异常、工具类、常量、配置)
├── auth          (认证：JWT、登录注册、登出)
├── user          (用户：个人信息、地址、偏好)
├── catalog       (商品：商品、SKU、分类、风味标签)
├── cart          (购物车：加购、修改、删除)
├── order         (订单：状态机、超时取消、订单项)
├── payment       (支付：模拟支付、回调幂等、退款)
├── inventory     (库存：预占、扣减、释放、流水)
├── subscription  (订阅：计划、周期任务、生成订单)
├── admin         (后台管理接口)
└── notification  (通知：邮件、站内信)
```



### 4.1 模块依赖规则

- `common` 被所有模块依赖，不依赖任何业务模块。
- `auth` 依赖 `user`，其他模块不依赖 `auth`。
- `order` 依赖 `cart`、`catalog`、`inventory`、`payment`、`user`。
- `subscription` 依赖 `order`、`catalog`、`user`。
- `admin` 依赖各业务模块，仅提供后台接口。
- 禁止循环依赖。

## 6. 关键技术决策

### 6.1 认证方案

- 无状态 JWT，Token 存入 Redis 并设置过期时间。
- 请求头：`Authorization: Bearer <token>`。
- 支持主动踢下线：删除 Redis 中 Token。
- Spring Security 过滤器链校验 Token，解析用户 ID 放入 SecurityContext。

### 6.2 库存防超卖

- 基于 MyBatis-Plus 的 `@Version` 乐观锁。
- 条件更新 SQL：

sql

```
UPDATE coffee_sku
SET stock = stock - #{num},
    version = version + 1
WHERE id = #{skuId}
  AND stock >= #{num}
  AND version = #{version}
  AND deleted = 0;
```



- 库存流水表 `inventory_log` 记录每次变更。
- 预占库存：下单时增加冻结库存，支付成功后真实扣减，取消释放。

### 6.3 订单超时

- 方案 A：RabbitMQ 死信队列（TTL + DLX）。
- 方案 B：Redis Key 过期监听。
- 方案 C：Spring Scheduling 定时扫描兜底。
- 采用 **A + C 组合**，保证可靠性。
- 超时时间：30 分钟。

### 6.4 支付回调幂等

- 支付单号唯一索引。
- 回调时先查询支付单状态，已处理直接返回成功。
- 使用 Redis 分布式锁防止并发回调。
- 支付成功后触发：库存真实扣减、订单状态流转、通知发送。

### 6.5 订阅定时任务

- 每日凌晨 2:00 扫描 `user_subscription` 中 `next_delivery_date <= 今日` 且状态为 `ACTIVE` 的订阅。
- 自动生成待支付订单，写入 `subscription_order`。
- 更新 `next_delivery_date` 为下一周期。
- 使用分布式锁防止多实例重复执行。

### 6.6 接口规范

- RESTful 风格，统一前缀 `/api/v1`。
- 统一响应结构：`{ code, message, data, traceId }`。
- 统一分页结构：`{ records, total, current, size }`。
- 错误码规范：401 未登录、403 无权限、4001 库存不足、4002 订单状态异常、4003 支付回调重复、4004 订阅状态异常、5000 系统异常。

### 6.7 统一异常处理

- `@RestControllerAdvice` 全局异常处理器。
- 业务异常：`BusinessException`，携带错误码。
- 参数校验异常：`MethodArgumentNotValidException`。
- 系统异常：`Exception`，返回 5000，记录日志。
- 所有异常返回统一响应结构。

### 6.8 日志与链路追踪

- 使用 MDC 注入 `traceId`，每个请求生成唯一 ID。
- 日志格式包含：时间、级别、traceId、线程、类名、消息。
- 关键业务节点打印日志：下单、支付、库存变更、订阅生成。
- 生产环境日志级别 INFO，开发环境 DEBUG。

### 6.9 缓存设计

| 缓存对象   | Key 格式                     | 过期时间 | 说明       |
| :--------- | :--------------------------- | :------- | :--------- |
| 用户 Token | `auth:token:{userId}`        | 7 天     | 支持踢下线 |
| 商品详情   | `catalog:product:{id}`       | 30 分钟  | 热点商品   |
| 订阅计划   | `subscription:plan:list`     | 1 小时   | 低频变更   |
| 分布式锁   | `lock:order:{orderNo}`       | 30 秒    | 支付回调   |
| 库存预占   | `inventory:preserve:{skuId}` | 30 分钟  | 可选       |

### 6.10 消息队列设计

| 交换机                  | 队列                      | 路由键              | 用途         |
| :---------------------- | :------------------------ | :------------------ | :----------- |
| `order.exchange`        | `order.timeout.queue`     | `order.timeout`     | 订单超时取消 |
| `order.exchange`        | `order.paid.queue`        | `order.paid`        | 支付成功通知 |
| `inventory.exchange`    | `inventory.release.queue` | `inventory.release` | 库存释放     |
| `notification.exchange` | `notification.queue`      | `notification`      | 通知发送     |

- 订单超时：延迟队列 TTL 30 分钟 + 死信交换机。
- 支付成功：异步通知库存、通知模块。
- 库存释放：取消订单后异步释放。

## 7. 核心流程时序

### 7.1 下单流程

text

```
用户 -> 前端 -> 订单接口 -> 校验购物车 -> 校验库存
-> 预占库存 -> 创建订单(待支付) -> 发送延迟消息(30min)
-> 返回订单号
```



### 7.2 支付流程

text

```
用户 -> 前端 -> 支付接口 -> 创建支付单 -> 模拟支付
-> 支付回调 -> 验签 -> 幂等校验 -> 更新支付单
-> 更新订单(已支付) -> 真实扣减库存 -> 发送通知
```



### 7.3 订单超时流程

text

```
延迟消息到期 -> 死信队列 -> 消费者
-> 查询订单状态 -> 若待支付 -> 取消订单 -> 释放预占库存
```



### 7.4 订阅生成流程

text

```
定时任务(每日 2:00) -> 扫描到期订阅
-> 生成待支付订单 -> 更新下次配送日期
-> 发送通知
```

### 8.1 仓库与工程结构

项目采用**单仓库多工程**模式，根目录统一管理文档、前后端代码、部署脚本。

```text
coffee-platform/
├── README.md                    # 项目说明、启动方式
├── .gitignore                   # 统一忽略 backend/target、frontend/node_modules 等
├── .editorconfig                # 统一代码风格
├── docs/                        # 所有项目文档
│   ├── 00-项目章程.md
│   ├── 01-MVP范围.md
│   ├── 02-需求规格说明书.md
│   ├── 03-架构设计.md
│   ├── 04-数据库设计.md
│   ├── 05-API设计文档.md
│   └── 06-前端设计.md
├── backend/                     # Spring Boot 后端工程
│   ├── pom.xml
│   ├── src/
│   └── .mvn/
├── frontend/                    # Vue3 前端工程
│   ├── package.json
│   ├── vite.config.ts
│   ├── tsconfig.json
│   └── src/
├── api-tests/                   # Bruno API 测试集合
│   ├── bruno.json
│   └── environments/
├── deploy/                      # 部署与运维
│   ├── docker-compose.yml       # MySQL、Redis、RabbitMQ
│   ├── nginx/
│   │   └── nginx.conf           # 生产环境前端托管 + /api 反向代理
│   └── sql/
│       └── init.sql             # 可选，Flyway 优先
└── scripts/                     # 常用脚本
    ├── start-backend.sh
    ├── start-frontend.sh
    └── init-db.sh
```

- 关键约定：

  - 根目录不放 `pom.xml` 和 `package.json`，前后端各自独立。
  - `docs/` 与代码同级，便于查阅与同步。
  - `api-tests/` 存放 Bruno API 测试集合，随仓库提交，与前后端契约同步维护。
  - `deploy/` 统一管理 Docker Compose、Nginx、初始化 SQL。
  - `scripts/` 提供本地一键启动脚本。

### 8.2 前后端联调方式

开发环境：

- 后端：`http://localhost:8080`
- 前端：`http://localhost:5173`
- 前端通过 Vite 代理 `/api` 到后端，避免跨域：

```ts
// frontend/vite.config.ts
server: {
  proxy: {
    '/api': {
      target: 'http://localhost:8080',
      changeOrigin: true
    }
  }
}
```

生产环境：

- Nginx 托管前端静态文件。
- Nginx 将 `/api` 反向代理到后端。
- 后端不负责托管前端页面，保持前后端分离。

## 9. 安全设计

| 风险         | 措施                      |
| :----------- | :------------------------ |
| 密码泄露     | BCrypt 加密               |
| 未授权访问   | JWT + Spring Security     |
| 水平越权     | 校验用户 ID 与资源归属    |
| 支付回调伪造 | 验签 + 幂等               |
| SQL 注入     | MyBatis-Plus 参数绑定     |
| XSS          | 前端转义 + 后端校验       |
| 重放攻击     | Token 过期 + 支付单号唯一 |
| 库存超卖     | 乐观锁 + 条件更新         |
