## 1. MVP 核心定义
以最短路径跑通“用户 -> 商品 -> 订单 -> 支付 -> 库存 -> 订阅”核心闭环。
非核心功能全部推迟到 P1/P2，避免过早陷入细节导致项目烂尾。

## 2. 优先级矩阵（MoSCoW）
| 优先级      | 说明                   | 处理策略                       |
| ----------- | ---------------------- | ------------------------------ |
| P0 (Must)   | 必须完成，构建核心闭环 | 第一版必须交付，否则项目不成立 |
| P1 (Should) | 加分项，视进度开发     | 核心闭环跑通后，有精力再做     |
| P2 (Could)  | 明确不做，未来扩展     | 第一版直接砍掉，不列入排期     |

## 3. P0 功能清单（必须完成）

### 3.1 用户模块
| 编号 | 功能     | 验收标准                                    |
| ---- | -------- | ------------------------------------------- |
| U-01 | 注册     | 支持邮箱/手机号注册，密码 BCrypt 加密       |
| U-02 | 登录     | 返回 JWT Token，Token 存入 Redis 并设置过期 |
| U-03 | 个人中心 | 查看/修改昵称、头像、手机号                 |
| U-04 | 收货地址 | 增删改查，支持设置默认地址                  |
| U-05 | 咖啡偏好 | 设置烘焙度、风味标签、处理法                |

### 3.2 商品模块
| 编号 | 功能     | 验收标准                                  |
| ---- | -------- | ----------------------------------------- |
| P-01 | 商品列表 | 分页、按关键词/烘焙度/风味筛选            |
| P-02 | 商品详情 | 展示商品信息、SKU 列表、库存              |
| P-03 | SKU 管理 | 支持 250g/500g、整豆/研磨，独立价格与库存 |

### 3.3 购物车与订单
| 编号 | 功能       | 验收标准                                       |
| ---- | ---------- | ---------------------------------------------- |
| C-01 | 加购       | 支持修改数量、删除、勾选                       |
| O-01 | 创建订单   | 结算购物车，生成订单与订单项                   |
| O-02 | 订单状态机 | 待支付 -> 已支付 -> 待发货 -> 已发货 -> 已完成 |
| O-03 | 取消订单   | 待支付状态可取消，释放预占库存                 |
| O-04 | 订单超时   | 30 分钟未支付自动取消                          |

### 3.4 支付与库存
| 编号   | 功能     | 验收标准                         |
| ------ | -------- | -------------------------------- |
| PAY-01 | 模拟支付 | 发起支付，返回支付单号           |
| PAY-02 | 支付回调 | 幂等处理，重复回调不重复扣库存   |
| INV-01 | 库存预占 | 下单时冻结库存                   |
| INV-02 | 库存扣减 | 支付成功后真实扣减，乐观锁防超卖 |
| INV-03 | 库存释放 | 取消订单释放预占库存             |

### 3.5 订阅模块
| 编号   | 功能         | 验收标准                                 |
| ------ | ------------ | ---------------------------------------- |
| SUB-01 | 订阅计划     | 支持周/月周期，展示价格与说明            |
| SUB-02 | 创建订阅     | 用户选择计划与偏好，生成订阅记录         |
| SUB-03 | 订阅管理     | 暂停、跳过、取消                         |
| SUB-04 | 定时生成订单 | 每日凌晨扫描到期订阅，自动生成待支付订单 |

## 4. P1 功能清单（加分项，视进度开发）
| 编号 | 功能     | 说明                                          |
| ---- | -------- | --------------------------------------------- |

| M-02 | 积分     | 积分抵扣、积分明细                            |
| N-01 | 通知     | 订单状态通知、订阅即将配送提醒（站内信/邮件） |

## 5. P2 功能清单（明确不做）
- Elasticsearch 搜索
- 推荐算法
- 多门店、多租户
- 真实支付/物流对接
- 复杂营销引擎

## 6. 验收标准
- P0 功能全部可用，且能通过 Postman/Swagger 完整演示。
- 前端页面能正常调用 P0 接口，无阻塞性 Bug。
- 核心链路通过并发测试（如 100 并发下单不超卖）。
- 支付回调具备幂等性，重复回调不产生脏数据。
- 订阅定时任务能正确生成订单并流转状态。
